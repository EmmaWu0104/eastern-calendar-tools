# 九宮飛星交接摘要

本文件整理九宮飛星第一階段至第七包完成後的功能狀態、規則、測試與後續待辦。現階段只做時間飛星，不做陽宅飛星。

## 功能範圍

目前支援：

- 運盤。
- 年盤。
- 月盤。
- 日盤。
- 時盤。
- 五盤整合顯示。
- 年、月、日、時四柱三煞方位標示。
- 綜合盤與個別年盤的太歲、歲破方位標示。
- UI 顯示九宮格。
- `starDisplayName` 圓圈數字顯示名稱，例如 `① 白貪狼`。
- 九宮格 UI 採中央星名、左下宮位洛書、右下方位名稱的格內版型。

明確排除：

- 陽宅飛星。
- 山星、向星。
- 宅運盤、坐向盤。
- 替卦、兼線、元龍。
- 吉凶、旺衰、斷語。
- 真太陽時。

## 時間規則

- 第一版使用手錶時間 / 瀏覽器本機時間。
- 第一版未套用真太陽時。
- 年盤沿用干支曆核心，以立春切換有效年份。
- 月盤沿用干支曆核心，以 12 節換月。
- 日盤使用 23:00 換日後的日柱。
- 時盤使用 23:00 換日後的日支與目前時支。
- 運盤依輸入時間的西元年份與三元九運判斷，不依立春切換。

## 五盤規則摘要

### 運盤

- 依三元九運。
- 幾運即幾星入中。
- 一律順飛。
- `2024-2043` 為九運，九入中宮。

### 年盤

- 使用立春換年後的有效年份。
- 年星入中公式：`11 - 西元年份各位數字和`，結果 normalize 到 `1-9`。
- 一律順飛。
- `2026` 丙午年為一白入中。

### 月盤

- 依年支三組與月支查表。
- 年支三組為 `子午卯酉`、`辰戌丑未`、`寅申巳亥`。
- 一律順飛。
- `2026` 丙午年巳月為五入中。
- 綜合盤月盤標題採「年支年 + 月建月」格式，例如 `午年未月`。
  月建直接讀取 `calendarResult.monthBranch`（經 monthly chart basis 傳遞），依 12 節換月；不是農曆月份，也不以整個國曆月份推算。

### 日盤

- 依 24 節氣分六組。
- 六組為 `冬至順`、`雨水順`、`穀雨順`、`夏至逆`、`處暑逆`、`霜降逆`。
- 依六十甲子序號 `mod 9` 查各組 `centers`。
- 順逆方向由節氣系統決定。

### 時盤

- 依目前節氣使用 `winterForward` 或 `summerReverse`。
- 使用 `dayBranch + hourBranch` 完整查表。
- 不用公式推導，避免流派差異與表格轉置風險。

## 核心檔案

- `src/flyingStars.js`：九宮飛星核心，包含飛佈、五盤計算、月盤表、日盤表與時盤表。
- `src/flyingStarViewModel.js`：五層綜合盤純顯示資料，固定各層順序並依相同宮位 id 取值。
- `src/main.js`：UI 呼叫五盤整合函式並 render 九宮飛星結果。
- `styles/main.css`：九宮飛星 UI 樣式。
- `tests/flying-stars-testcases.json`：九宮飛星測試資料。
- `tests/run-tests.js`：測試 runner，固定測試基準時區並執行干支曆與九宮飛星測試。
- `docs/03_九宮飛星規則設計草案.md`：規則設計。
- `docs/04_九宮飛星資料結構與測試計畫.md`：資料結構與測試計畫。
- `docs/05_九宮飛星流派差異與待確認事項.md`：流派差異與待確認事項。
- `docs/06_九宮飛星交接摘要.md`：本交接摘要。

## UI 格內版型

九宮飛星畫面最上方為五層綜合盤，下方保留運盤、年盤、月盤、日盤、時盤五個獨立盤。
綜合盤與五個獨立盤均使用同一次 `calculateAllFlyingStarCharts` 回傳結果，沒有在 UI 重新計算飛星。

五層綜合盤：

- 固定依運、年、月、日、時順序疊加。
- 桌機每層顯示固定標籤、圓圈數字與九星名稱，例如 `運 ⑧ 白左輔`。
- 手機以 media query 隱藏綜合盤的九星名稱，只保留標籤與圓圈數字，例如 `運 ⑧`；不建立第二份綜合盤 DOM。
- 每個宮位均依相同 `palace.id` 從五盤取值。
- 年、月、日、時各依該層 chart basis 的地支判斷三煞方；綜合盤把「三」圓圈附在對應時間層飛星項目後方，不使用宮位共用三煞 marker。
- 綜合盤下方方位摘要格式為 `太歲方｜歲破方｜三煞：年方 月方 日方 時方`，例如 `太歲南｜歲破北｜三煞：年北 月西 日南 時西`。
- 太歲與歲破維持宮位層級 marker，不移入年層飛星項目。
- 左下角保留宮位名稱與洛書數，右下角保留方位名稱。
- 摘要直接使用各 chart basis、方向與入中星，包含運盤元別、年盤元別、日／時陰陽遁；月摘要沿用月建格式，例如 `午年未月`。

五個獨立盤每格顯示採用：

- 正中央：九宮飛星顯示名稱，例如 `⑨ 紫右弼`。
- 年、月、日、時盤在各自三煞方宮位顯示「三」圓圈；運盤不顯示三煞。
- 個別年盤另在對應宮位顯示太歲與歲破，與年三煞同宮時由 marker stack 同時排列。
- 運盤不顯示太歲或歲破。
- 左下角：宮位名稱與洛書數，例如 `巽4`。
- 右下角：方位名稱，例如 `東南`。

方位名稱是顯示層 label，依宮位 id 對應固定文字。五層綜合盤是純 UI 顯示功能，未影響九宮飛星計算規則。
獨立盤持續顯示完整九星名稱；獨立運盤、年盤與月盤的 basis 也分別顯示元別、元別年柱與年支年＋月建月。月盤 basis 的 label 為「月盤依據」，例如「月盤依據：午年未月」。

## 四柱三煞方位

- `申、子、辰`：三煞在南，對應 `li`／離宮。
- `巳、酉、丑`：三煞在東，對應 `zhen`／震宮。
- `寅、午、戌`：三煞在北，對應 `kan`／坎宮。
- `亥、卯、未`：三煞在西，對應 `dui`／兌宮。
- 年三煞使用 `charts.annual.basis.yearPillar` 的年支。
- 月三煞使用 `charts.monthly.basis.monthBranch`。
- 日三煞使用 `charts.daily.basis.dayBranch`。
- 時三煞使用 `charts.hourly.basis.hourBranch`。
- 四層資料均出自同一次 `calculateAllFlyingStarCharts(calendarResult, inputDateTime)`，不讀取現在時間、月曆瀏覽月份或舊畫面 state。
- 本功能只做方位標示，不改變九宮飛星、干支曆、節氣或奇門遁甲計算規則。

## 測試狀態

目前測試重點：

- `flyStars` 順飛 / 逆飛。
- 運盤九運。
- 年盤 `2026` 一白入中。
- 月盤三組年支。
- 日盤六組節氣系統。
- 時盤 `winterForward` / `summerReverse` 完整查表案例。
- 23:00 換日。
- 夏至前後順逆切換。
- 五盤整合。
- 三煞十二地支完整 mapping 與方向至宮位 mapping。
- 四柱三煞摘要、綜合盤逐層 marker、個別盤 marker 與個別年盤太歲／歲破 marker stack。
- 連續查詢重新建立四層三煞 view model，不殘留前次摘要或 marker。

目前測試結果：

- `npm test` 通過，九宮飛星 `60 cases`。
- `TZ=UTC npm test` 通過，九宮飛星 `60 cases`。
- 四柱三煞與飛星 marker view model 回歸測試 `45 cases`，兩種執行方式均通過。
- 測試 runner 固定 `Asia/Taipei` 作為測試基準。這是目前測試案例的手錶時間基準，不代表產品邏輯使用 UTC。

## 人工驗證建議案例

| 輸入時間 | 驗證重點 |
| --- | --- |
| `2026-05-29T09:30` | 運盤九入中；年盤一入中；月盤五入中；日盤七入中；時盤六入中 |
| `2026-05-29T22:59` | 日盤 basis：癸卯；時盤 basis：癸卯、亥時 |
| `2026-05-29T23:00` | 日盤 basis：甲辰；時盤 basis：甲辰、子時 |
| `2026` 夏至前後 | 夏至前日盤 / 時盤順飛；夏至後日盤 / 時盤逆飛 |

## 後續待辦

- 未來可做真太陽時，但需等核心穩定後再做，且會影響日柱、時柱、節氣交界判斷。
- 若要處理陽宅飛星，必須另開模組，不要混入目前時間飛星。
- 若要加入吉凶斷語，需另建資料來源與流派規則，不要直接寫死在目前核心。
- 可考慮增加匯出 JSON / 複製盤面功能。
- 可考慮加入人工驗證快速按鈕，但不要影響核心。
